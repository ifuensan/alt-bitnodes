## MODIFIED Requirements

### Requirement: The crawler assigns each onion to one Tor instance

The crawler configuration generated by `install.sh` SHALL list every Tor
SocksPort (the default 9050 plus all pool ports) in `tor_proxies`, so the
whole pool carries onion traffic. Selection among those proxies SHALL be
deterministic per destination: an onion address SHALL always be dialed
through the same instance, chosen by a stable hash of the address that does
not vary between processes, restarts or hosts. `crawl.py` and `ping.py` SHALL
use the same selection, so both feed the same instance for a given onion and
share the circuits it holds.

Selection SHALL be governed by the `tor_proxy_affinity` config key, default
enabled; when disabled, selection falls back to uniform random choice per
dial. Proxy selection for `ipv4_proxies` and `ipv6_proxies` SHALL remain
random, as those exist to spread source addresses rather than to reuse
circuits.

**Rationale**: a Tor client keeps per-onion state — descriptor, introduction
circuit, rendezvous circuit — and reuses it for a later stream to the same
service while the circuit is not expired. Random per-dial selection discards
that state pool-size times over, and makes `MaxCircuitDirtiness` almost inert
because a revisit lands on the daemon holding the warm circuit with
probability 1/N.

#### Scenario: tor_proxies lists the whole pool
- **WHEN** `install.sh` generates `crawl.f9beb4d9.conf`
- **THEN** `tor_proxies` contains `127.0.0.1:9050` through the last pool port

#### Scenario: The same onion always gets the same instance
- **WHEN** the same `.onion` address is dialed repeatedly, from either
  `crawl.py` or `ping.py`, in any process and after a restart
- **THEN** every dial uses the same entry from `tor_proxies`

#### Scenario: Different onions spread across the pool
- **WHEN** a large set of distinct `.onion` addresses is dialed
- **THEN** the dials distribute across all entries of `tor_proxies`

#### Scenario: Affinity can be switched off without a code change
- **WHEN** `tor_proxy_affinity` is set to `False`
- **THEN** each dial picks an entry of `tor_proxies` at random, as before
